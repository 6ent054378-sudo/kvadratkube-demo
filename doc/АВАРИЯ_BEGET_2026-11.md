# Авария Beget 1–2 ноября 2026 и что с сайтом

## Что случилось

Сайт `kvadratvkube26.ru` перестал открываться не из-за наших правок.
Beget (хостинг, где лежит сайт) 1–2 ноября 2026 попал под кибератаку:
по их официальной хронологии злоумышленники запустили вредоносное ПО
«для удаления данных с серверов», после чего все серверы отключили от сети.
Виртуальный хостинг восстанавливают поэтапно, данные — из резервных копий.

Проверено 5 ноября 2026:

| Проверка | Результат |
|---|---|
| `45.130.41.213` (IP сайта), порты 21/22/80/443 | не отвечает, из 6 стран — timeout |
| `cp.beget.com` (панель) | `502 Bad Gateway` из Europe/Asia/US |
| `api.beget.com` | бесконечный редирект |
| `ns1/ns2.beget.com` | живы, отдают A `45.130.41.213` |
| `beget.com` | живой, на главной — сообщение об атаке |

То есть домен исправен и делегирован, DNS отвечает, но сервер с сайтом
выключен. Это авария провайдера, ждём их восстановления.

## Чтобы вернуть домен

Вариант 1 (ничего не делать): как только Beget поднимет виртуальный хостинг,
сайт откроется сам — DNS уже указывает на их сервер. После восстановления
нужно перезалить `index.html` (в нём новая отправка форм) по FTP
`deploy@stavevee.beget.tech`.

Вариант 2 (вернуть за 3 минуты, без ожидания Beget): перевести домен
на GitHub Pages. Делает Дмитрий в своём кабинете RU-CENTER (nic.ru),
пароли никому передавать не нужно:

1. nic.ru → «Домены» → `kvadratvkube26.ru` → «DNS-серверы» →
   указать `ns3-l2.nic.ru`, `ns4-l2.nic.ru`, `ns5-l2.nic.ru` (сохранить).
2. Там же → «DNS-записи»: убрать старые A, добавить четыре A для `@`:
   `185.199.108.153`, `185.199.109.153`, `185.199.110.153`, `185.199.111.153`;
   для `www` — CNAME `6ent054378-sudo.github.io`.
3. Написать нам — включаем домен в настройках GitHub Pages и HTTPS.
